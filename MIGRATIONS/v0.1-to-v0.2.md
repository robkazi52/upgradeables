# Migrating from v0.1 to v0.2

The registry moves from `0.1.0` to `0.2.0`; operational metadata moves to schema
`2.0.0`; all 96 semantically hardened packages move from `1.0.0` to `1.1.0`.
No package slug or historical alias was removed.

Consumers should regenerate pinned catalogs and update `slug@1.0.0` references to
`slug@1.1.0`. Before activation, read `os_role`, `pipeline_stages`,
`best_fit_tasks`, `avoid_when`, `mechanism_basis`, interaction reasons,
counterbalances, and redundancy notes. Legacy `recommended_skill_types` and
`non_triggers` remain populated but now mirror the concept-specific task-fit data.

Recipes are version `1.1.0` and add activation boundaries, required rationales,
important exclusions, high-cost components, and an over-inclusion rule. Bundles
add a required/optional split, critical interactions, and an excess boundary.

Behavior cases are specifications, not evidence that a model passed. Use the eval
adapter interface to run an actual model, and keep static validation results
separate. Packages marked `modern-interpretation` or `provisional` must not be
presented as fully recovered historical mechanisms.
