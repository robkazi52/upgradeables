# Anti-Tunnel Vision — Behavioral Expectations

## Positive Activation

- **Given:** The team has fixated on the new database query although saturation and cache invalidation are also plausible.
- **Expect:** Compares query regression against cache invalidation using the cheapest discriminating metrics, then selects the explanation supported by timing and cache data. Result: A bounded, evidence-selected diagnosis with one residual uncertainty noted.
- **Reject:** Omitting the mechanism or instead doing this: List every imaginable outage cause or preserve the query hypothesis after contrary evidence.

## Negative Activation

- **Given:** the answer is directly established by a locked source
- **Expect:** Remain inactive; do not begin the package-specific first step: State the current favored hypothesis or plan and the evidence supporting it.
- **Reject:** Activating Anti-Tunnel Vision solely because its name appears relevant

## Precedence Or Conflict

- **Given:** If a hard veto eliminates a branch, do not keep it alive for balance.
- **Expect:** Honor the conflict rule and preserve this invariant: make the favored path explicit
- **Reject:** Silently violating the stated precedence for Anti-Tunnel Vision

## Failure Boundary

- **Given:** unbounded ideation
- **Expect:** Stop, narrow, abstain, or escalate while preserving: explicitly test at least one plausible rival before a costly commitment
- **Reject:** Claiming a successful Anti-Tunnel Vision result past this boundary

## Strong Model Scaling

- **Given:** a capable host can compress the workflow
- **Expect:** explicitly test at least one plausible rival before a costly commitment
- **Reject:** dropping the mandatory invariant

## Distinctive Mechanism

- **Given:** A draft commits to the first plausible cause in an ambiguous incident.
- **Expect:** The skill names a materially different rival and a decisive evidence check before commitment.
- **Reject:** The skill merely says to think broadly or produces an unbounded brainstorm.

These are provider-neutral behavioral specifications. Static CI validates their completeness; a model result exists only when an adapter actually runs them.
