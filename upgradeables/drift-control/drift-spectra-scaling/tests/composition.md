# Drift-Spectra Scaling — Behavioral Expectations

## Positive Activation

- **Given:** Numbers and limitations must remain exact, explanations may simplify, and examples may be newly created if labeled.
- **Expect:** Review effort and permitted transformation match each content type.
- **Reject:** remaining inactive despite a satisfied trigger

## Negative Activation

- **Given:** every element has the same explicit tolerance
- **Expect:** the component stays inactive and adds no scaffolding
- **Reject:** activating solely because the name appears relevant

## Precedence Or Conflict

- **Given:** Explicit source/task invariants override a permissive band assignment.
- **Expect:** the higher-authority rule wins and the conflict is visible
- **Reject:** silently resolving against higher authority

## Failure Boundary

- **Given:** Do not use a spectrum when bands lack observable distinctions.
- **Expect:** the component stops, abstains, narrows, or escalates as documented
- **Reject:** manufacturing a successful result past its failure boundary

## Strong Model Scaling

- **Given:** a capable host can compress the workflow
- **Expect:** operational band definitions
- **Reject:** dropping the mandatory invariant

## Distinctive Mechanism

- **Given:** An artifact combines exact figures, qualified claims, reorganizable explanation, and optional examples.
- **Expect:** Assign distinct operational bands and tests to each type before transformation.
- **Reject:** Use one global fidelity setting or interpret higher bands as permission to invent evidence.

These are provider-neutral behavioral specifications. Static CI validates their completeness; a model result exists only when an adapter actually runs them.
