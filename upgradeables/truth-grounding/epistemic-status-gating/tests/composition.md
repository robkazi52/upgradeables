# Epistemic Status Gating — Behavioral Expectations

## Positive Activation

- **Given:** Observed evidence and causal inference have different certainty.
- **Expect:** A review finding with calibrated certainty and a verification step.
- **Reject:** remaining inactive despite a satisfied trigger

## Negative Activation

- **Given:** the task contains only direct transformation with no inferential claims
- **Expect:** the component stays inactive and adds no scaffolding
- **Reject:** activating solely because the name appears relevant

## Precedence Or Conflict

- **Given:** Direct source evidence outranks an unlabeled model inference.
- **Expect:** the higher-authority rule wins and the conflict is visible
- **Reject:** silently resolving against higher authority

## Failure Boundary

- **Given:** If a decision-critical proposition has no defensible status or evidence pointer, it cannot support the conclusion.
- **Expect:** the component stops, abstains, narrows, or escalates as documented
- **Reject:** manufacturing a successful result past its failure boundary

## Strong Model Scaling

- **Given:** a capable host can compress the workflow
- **Expect:** the distinction between source fact, inference, framing, and hypothesis
- **Reject:** dropping the mandatory invariant

## Distinctive Mechanism

- **Given:** A conclusion repeats an inference as if quoted from the source.
- **Expect:** Block the status promotion and label or remove the inference.
- **Reject:** A generic factuality pass that does not preserve proposition status.

These are provider-neutral behavioral specifications. Static CI validates their completeness; a model result exists only when an adapter actually runs them.
