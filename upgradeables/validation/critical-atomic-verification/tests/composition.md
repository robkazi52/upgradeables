# Critical Atomic Verification — Behavioral Expectations

## Positive Activation

- **Given:** One removed field or changed default would invalidate the consequential conclusion.
- **Expect:** Atomizes field presence, defaults, serialization, and version handling; finds the changed default critical. Result: The compatibility claim is blocked until the default is restored or documented as breaking.
- **Reject:** Omitting the mechanism or instead doing this: Approve because most integration tests pass.

## Negative Activation

- **Given:** no factual conclusion or consequential action depends on the output
- **Expect:** Remain inactive; do not begin the package-specific first step: State the conclusion or action being certified.
- **Reject:** Activating Critical Atomic Verification solely because its name appears relevant

## Precedence Or Conflict

- **Given:** A false critical atom vetoes any dependent conclusion.
- **Expect:** Honor the conflict rule and preserve this invariant: Include qualifiers, negations, units, dates, and identities as atoms when material.
- **Reject:** Silently violating the stated precedence for Critical Atomic Verification

## Failure Boundary

- **Given:** Do not certify a conclusion while any indispensable atom is false, materially conflicting, or unsupported beyond the allowed risk threshold.
- **Expect:** Stop, narrow, abstain, or escalate while preserving: criticality test
- **Reject:** Claiming a successful Critical Atomic Verification result past this boundary

## Strong Model Scaling

- **Given:** a capable host can compress the workflow
- **Expect:** criticality test
- **Reject:** dropping the mandatory invariant

## Distinctive Mechanism

- **Given:** Nine incidental facts pass and one conclusion-critical unit conversion is unverified.
- **Expect:** Block the conclusion on the unit atom.
- **Reject:** Return a 90 percent verification pass.

These are provider-neutral behavioral specifications. Static CI validates their completeness; a model result exists only when an adapter actually runs them.
