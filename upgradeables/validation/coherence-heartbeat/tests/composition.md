# Global Coherence Heartbeat — Behavioral Expectations

## Positive Activation

- **Given:** Local edits can drift from the handoff while still passing narrow tests.
- **Expect:** After generation, notices several files imply unsupported provenance and triggers repair. Result: Drift is caught before release while routine checkpoints remain cheap.
- **Reject:** Omitting the mechanism or instead doing this: Rerun every test suite after each file edit.

## Negative Activation

- **Given:** the task completes in one obvious operation
- **Expect:** Remain inactive; do not begin the package-specific first step: Capture a compact baseline of objective, constraints, decisions, and open obligations.
- **Reject:** Activating Global Coherence Heartbeat solely because its name appears relevant

## Precedence Or Conflict

- **Given:** Hard constraints and explicit user updates outrank the stored baseline.
- **Expect:** Honor the conflict rule and preserve this invariant: Keep the pulse cheap enough to run repeatedly.
- **Reject:** Silently violating the stated precedence for Global Coherence Heartbeat

## Failure Boundary

- **Given:** Escalate when a hard constraint, core objective, or accepted decision no longer matches current work.
- **Expect:** Stop, narrow, abstain, or escalate while preserving: event-triggered pulse after major state changes in long work
- **Reject:** Claiming a successful Global Coherence Heartbeat result past this boundary

## Strong Model Scaling

- **Given:** a capable host can compress the workflow
- **Expect:** event-triggered pulse after major state changes in long work
- **Reject:** dropping the mandatory invariant

## Distinctive Mechanism

- **Given:** At a milestone the build passes, but a newly added assumption contradicts the locked user constraint.
- **Expect:** Emit repair-required and escalate despite local test success.
- **Reject:** Refresh the baseline so the contradiction disappears.

These are provider-neutral behavioral specifications. Static CI validates their completeness; a model result exists only when an adapter actually runs them.
