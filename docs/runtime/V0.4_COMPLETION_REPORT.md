## Compiler

The compiler accepts a v0.3 `TaskResolution` or resolves task text through the
v0.3 producer, then deterministically activates selected components, routes
non-instruction mechanisms into typed channels, applies authority precedence,
fails closed on unresolved conflicts, deduplicates overlapping controls, and
compresses directive levels within the requested budget. See the
[compiler design](DIRECTIVE_COMPILER.md) and [RuntimePlan contract](RUNTIME_PLAN.md).

## Adapters

Implemented and deterministically tested adapters are documented in
[Runtime adapters](ADAPTERS.md):

- generic composition: returns a separate runtime block by default and supports
  managed append/prepend modes while preserving base instructions;
- Ollama: an end-to-end compile/compose/execute/normalize/artifact facade,
  native `/api/chat` request construction, explicit read-only discovery,
  completed-response normalization, and caller-supplied NDJSON stream
  normalization;
- OpenAI-compatible: conservative `/v1/chat/completions` request construction,
  explicit `/models` discovery, explicit non-streaming execution, completed
  response normalization, and caller-supplied SSE stream normalization;
- OpenAI Agents SDK: optional dependency-free application to static, synchronous
  dynamic, and asynchronous `instructions` surfaces, including idempotent managed
  replacement.

Structured state, validators, orchestration, tool requirements, and output
contracts remain visible to hosts; Ollama and Chat Completions request builders
do not misrepresent those channels as native capabilities.

### Local Ollama readiness

Install the candidate from the source checkout first:

```bash
python -m pip install -e .
```

End-to-end dry run; this resolves and compiles the task, prints the request and
plan with their hashes, and makes no network request or artifact write:

```bash
upgradeables run ollama --model REPLACE_WITH_INSTALLED_MODEL --task "review this function for a regression" --dry-run --format json
```

Read-only discovery of an already configured local Ollama server and exact model
identifier; this never pulls or loads a missing model:

```bash
python -c "import json; from upgradeables_harness.runtime.adapters.ollama import discover; print(json.dumps(discover('http://127.0.0.1:11434', 'REPLACE_WITH_INSTALLED_MODEL'), indent=2))"
```

Explicit local inference; replace the model name with one already installed.
This records a fresh six-file artifact set under `.upgradeables/runs`:

```bash
upgradeables run ollama --model REPLACE_WITH_INSTALLED_MODEL --task "return exactly: READY" --endpoint http://127.0.0.1:11434 --options-json '{"temperature": 0}' --output-root .upgradeables/runs
```

Optional integration smoke for a running loopback server and an already
installed model:

```powershell
$env:UPGRADEABLES_RUN_OLLAMA_INTEGRATION = "1"
$env:UPGRADEABLES_OLLAMA_MODEL = "REPLACE_WITH_INSTALLED_MODEL"
$env:UPGRADEABLES_OLLAMA_ENDPOINT = "http://127.0.0.1:11434"
python tests/test_ollama_integration_v04.py -v
```

The smoke skips when it is not explicitly enabled, the server is absent, or the
exact model is not installed. It never downloads a model. No live Ollama model
inference was run for this report, so no local-model result is claimed.

## Evaluation harness

The offline-first harness is documented in [Runtime evaluation](EVALUATION.md)
and its fuller [evaluation methodology](../../research/runtime/evaluation-methodology.md).
It implements:

- `baseline`, `static-full`, and `adaptive-runtime` conditions;
- a fixed, versioned, non-adaptive
  [static-full comparator](../../evals/runtime/static-full-v1.txt);
- deterministic balanced condition permutations within task/trial blocks;
- append-and-flush raw JSONL observations with complete requests, unmodified
  responses, condition labels, grader records, statuses, provenance, and hashes;
- typed ungraded records for condition, adapter, and grader failures;
- task-level paired descriptive comparisons across repeated trials;
- immutable experiment directories containing `manifest.json`,
  `raw-results.jsonl`, `summary.json`, and `report.md`.

The bundled CC0 [synthetic-runtime-v1 suite](../../evals/runtime/suites/synthetic-runtime-v1.json)
contains ten tasks spanning constraint following, source grounding, citation
fidelity, local editing, debugging repair, code review, long-context state,
alternative hypotheses, structured output, and stopping/overwork.

Objective deterministic graders currently support:

- exact text after outer-whitespace normalization;
- case-insensitive `contains-all`;
- case-insensitive `contains-any`;
- excluded-string checks;
- exact field/value checks on a JSON object.

The exact offline plumbing command is:

```bash
upgradeables eval run synthetic-runtime-v1 --adapter mock --trials 1 --experiment-id synthetic-runtime-v1-mock --output-root .evals/upgradeables
```

The mock adapter emits grader-compatible fixture output. It validates harness
plumbing only and is not model-quality evidence. Human grading and model-as-judge
execution are not implemented as core graders. The current reporter is
descriptive and does not yet compute task-clustered confidence intervals,
bootstrap uncertainty, latency, provider usage/cost, or family-level paired
deltas.

## Limitations

- No empirical superiority claim has been established. Mock results are plumbing
  evidence only.
- No paid API was called while building or validating v0.4.
- No model was downloaded and no live Ollama model inference was run. The
  optional integration smoke skips unless explicitly enabled with an exact
  already-installed model.
- No universal/transparent localhost proxy is implemented.
- MCP exposure is optional and deferred; no MCP server is implemented.
- LangChain middleware and an OpenAI Responses API adapter are not implemented.
- Live NDJSON/SSE connection ownership remains with the caller; the included
  helpers normalize caller-supplied stream chunks.
- Capability discovery is conservative. OpenAI-compatible `/models` proves
  identity only unless the caller supplies declarations; Ollama metadata does
  not prove that a model honors every declared behavior.
- The eval CLI runs only the offline mock adapter. Live adapter experiments
  require explicit integration code and user authorization.
- The bundled ten-task suite is synthetic and small. It cannot establish general
  agent effectiveness or model equivalence.
- The reporter does not yet implement inferential confidence intervals or all
  cost/latency fields in the research protocol.
- The local evidence is tied to candidate implementation commit `32cd0ca` plus
  the documentation and CI changes in this report's branch.
