# v0.3 Input Contract

The v0.4 runtime compiler consumes the deterministic v0.3 `TaskResolution`
object. It does not repeat task classification, recipe ranking, project
inspection, or component selection.

## Producer

Use `upgradeables_harness.resolver.task.resolve_task(task, project=...)`, or the
equivalent `upgradeables task ... --json` command. The accepted schema is
[`spec/harness/TASK_RESOLUTION_SCHEMA.json`](../../spec/harness/TASK_RESOLUTION_SCHEMA.json).

The compiler requires:

- `schema_version == "1.0.0"`;
- `selection_only == true`;
- a non-empty `query` and `normalized_task`;
- `task`, `environment`, `failure_modes`, and `complexity` objects;
- the selection groups `required_by_recipe`, `trigger_likely`, `conditional`,
  `optional`, `excluded`, and `needs_agent_evaluation`;
- component records with a canonical `slug` and pinned `version`.

Unknown additive fields are retained by the producer and ignored by the v0.4
compiler. A missing required field, a future incompatible schema version, an
unknown component, or a component-version mismatch fails closed.

## Activation boundary

v0.3 is deliberately selection-only. v0.4 activates:

- `required_by_recipe` components;
- `trigger_likely` components whose v0.3 deterministic rules observed a
  positive trigger.

It does not silently activate `conditional`, `optional`, or
`needs_agent_evaluation` components. Those groups remain visible in compile
explanations. Items in `excluded` remain excluded.

The v0.3 complexity ceiling limits runtime density. `hard_restrictions` become
authority-preserving instructions, and `required_checks` become validator
requirements. For example, `environment.review_only == true` suppresses editing
and repair controls even if malformed external input places one in an active
group.

## Canonical hashing

For reproducibility, the compiler hashes the UTF-8 bytes of the complete
`TaskResolution` serialized as JSON with sorted keys, compact separators, and
no ASCII escaping. The hash is written as `sha256:<hex>`.

The task text may contain sensitive data. The hash is safe to use as a cache
key, but it is not an anonymization guarantee and must not be treated as one.

## Compatibility

The v0.4 compiler remains compatible with v0.3 projects whose
`.upgradeables/config.json` has no `runtime` or `models` key. Runtime compilation
is an explicit CLI/API action; project initialization does not globally inject
instructions.
