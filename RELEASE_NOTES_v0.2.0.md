# Upgradeables v0.2.0 — Semantic Hardening

This release turns the operational library into a package-specific, model-readable
set of building blocks while preserving the recovered historical record.

## Measured release scope

- 96 baseline operational packages reviewed; 96 have a v0.2 disposition.
- 84 `PASS`; 12 `BLOCKED_BY_SOURCE_GAP`; 0 missing; 0 unreviewed.
- 96 concept-specific examples and 576 structured behavioral specifications.
- 6 narrow deterministic package checks; no model-behavior pass is claimed.
- 16 recipes reviewed and 8 curated bundles hardened.
- 6 adapter guides expanded under one provider-neutral adapter contract.
- 6 worked community Skills covering research, coding, long context, creative
  ideation, high-stakes evidence, and architecture.
- 101 historical-only and 14 unresolved records preserved.
- 30 unit tests and 838 internal links passed in the release validation run.
- 4 checksummed release assets generated reproducibly.

## Highlights

Every operational package now explains its purpose, problem, OS role, pipeline
stage, best-fit tasks, exclusions, mechanism basis, procedure, interactions,
counterbalances, redundancy, failure boundary, strong-model invariant, provenance,
example, and behavior cases. QMS modes remain operationally distinct, while
distributed execution is never claimed for sequential self-review.

The registry is `0.2.0`, operational metadata uses schema `2.0.0`, and all
semantically hardened packages are `1.1.0`. No package was removed, merged, or
deprecated. Source-gap packages are labeled modern/provisional rather than being
filled with invented historical detail.
